# Exactness obligations for the FP-side BV division bit-blaster

`crates/ay-theories/fp/src/bv_circuits.rs` bit-blasts the SMT-LIB
`bvudiv`/`bvurem`/`bvsdiv`/`bvsrem`/`bvsmod` family inside the FP solver's
variable space. This directory holds the generators for the SMT obligations
that pin that encoding to the standard's semantics. Each generator writes
`.smt2` files into `./ctl`; every obligation asserts the **negation** of the
property, so `unsat` means the encoding is exact and `sat` means it is not.

    python3 gen_obligations.py 4 8 12 16 20      # full miters, per width
    python3 gen_uf.py 32                         # sign fix-up, divider uninterpreted
    python3 gen_negative_controls.py 8 32        # mutants that MUST come back sat
    python3 gen_split.py                         # width-32 miter, split on the divisor's msb
    python3 gen_split_zero.py                    # the b = 0 case of that split
    python3 gen_w32_chain.py                     # width-32 structural properties

Run each file under z3, cvc5 and bitwuzla. Recorded verdicts, oracle versions
and runtimes live in
the development design notes.

## What is proven where

The encoding is two layers, and they are discharged separately so that neither
proof has to carry the other's cost.

**Layer 2 — the signed sign fix-up** (`gen_uf.py`). AY normalises the operands
to magnitudes, calls the unsigned divider **once**, and fixes the sign of the
result; SMT-LIB instead defines `bvsdiv`/`bvsrem`/`bvsmod` by a four-way case
split over four separate divider calls. That the two agree is a property of the
case split alone — it holds for *any* function in the divider's place — so the
obligation is stated with the divider left uninterpreted. `U3`/`U4`/`U5` are
`unsat` at the real width 32 on all three oracles in milliseconds, and their
mutants `U3N`/`U4N`/`U5N` are `sat` on all three.

**Layer 1 — the unsigned restoring divider** (`gen_obligations.py`, `O1`/`O2`,
and the fused `O6`/`O7`). This is a divider miter, and it does not scale: see
the measured ladder in the report. It is discharged in full at the smaller
widths and, at width 32, by the properties in `gen_w32_chain.py` plus the
divisor case split in `gen_split.py`.

## The trap in the older `divk.py` artifacts

A previous attempt at this fix used a magic-number rewrite `bvsdiv x K` →
`(x * M) >>s s`, generated by a helper `divk.py` whose admissibility bound
`floor(2^(W-1)/K)` is off by one at `K = 2`: it admits `d = +2^30 · 2` through
`bvmul` wraparound, and `ctl/divk_check_2.smt2` comes back **`sat`** on all
three oracles. Nothing here uses that route — there are no magic numbers and no
per-constant table, so there is no bound to get wrong.
